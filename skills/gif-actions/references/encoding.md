# 叠字、编码与可选排错

普通出片直接切帧、编码和交付；编码工具自带的可读性检查已足够，不再追加视觉验收。要精确文字时叠字。只有用户要求排错、调整已有文件或限制体积时，才使用下面相应工具；这些本地操作不触发新的图像生成。

## 修改指定成品

先根据当前这组的编号、文件或制作记录定位用户的目标。“第五张换字”“这张调快点”只处理指定目标，不自动扩成一组。保留原文件，另存 `-v2.gif` 等新版本，不默认使用 `--force`。

**换字幕。** `caption_gif.py` 负责把文字烧入画面，不会删除旧字。优先用已有的 `clean.gif`、`raw.gif` 等无字成品重新叠字；其次复用原始帧或帧表重新本地合成。这个路径不调用图像生成。

```sh
python scripts/caption_gif.py source/05-clean.gif "别催了" 05-v2.gif
```

只有带字成品、没有干净源素材时，不能把直接叠新字宣称为完成替换。说明旧字幕已经烧入、现有叠字工具无法移除，根据用户对画面保留的要求确定是否提供干净源或接受覆盖原字幕区域等本地处理；不自动重抽图像。

**调速度。** 有源帧就复用；没有时，使用新目录从现有成品提帧并读取逐帧时长，再按比例调整。保留原本长短停顿的关系，四舍五入到正的 10 毫秒倍数；不要为了调快而把所有帧都改成等长。

```sh
python scripts/inspect_gif.py 05.gif --extract frames-05-v2 --json
# 仅当读出的原时长为 200,150,180,600 ms，下面是约快 25% 的例子：
python scripts/pack_gif.py frames-05-v2 05-faster.gif --delay-ms 160,120,140,480
```

此处 `inspect_gif.py` 用来提取素材和时间信息，不做视觉验收，不需要 `--sheet`、`--chat` 或 `--compare`。它可能因动作幅度等提示返回 1，帧仍可能已正常导出；不能把这个返回码当作重新生成信号。提取目录不覆盖已有文件，解码错误按实际技术错误处理。

换主体、换动作等确需新画面的指定款，按原有参考与用户要求生成一次；仍只改指定数量。以某款继续创作一组，则回到 [需求理解](requests.md) 的新创作分支。

## 可选排错，不是默认流程

```sh
python scripts/inspect_gif.py reaction.gif --sheet sheet.png --chat chat.png
```

命令报告尺寸、帧数、时长、循环和首尾差异。退出码 1 混合了循环、动作幅度、时长等提示，不代表每项都须修复，更不能触发重抽。`sheet.png` 是单个 GIF 的静态联系表；`chat.png` 是 96 像素下的首帧与像素变化最大帧，后者不等于笑点。它们不是九个独立成品的九宫格，也不负责评定人物辨识或好笑程度。

## 中文叠字

```sh
python scripts/caption_gif.py reaction.gif "我真的会谢" captioned.gif --from-ms 600
```

字号自动适应画面，默认白字黑边放在底部。`--position top|center|bottom` 改位置，`--from-ms` 和 `--to-ms` 让字幕卡在爆点出现，`\n` 换行，`--font` 指定字体。没传 `--font` 时查找系统中文字体，找不到会报错。字幕尽量短大，不追加小图审美验收。

## 改节奏或尺寸

先拆出逐帧，再按下文的方式重新编码。拆帧时命令会打印原始逐帧时长。只改尺寸时沿用这些时长；普通调快或调慢按上面的比例调整方法保留停顿关系。以下统一时长命令仅适用于用户明确要求所有帧等节拍的情况。

```sh
python scripts/inspect_gif.py reaction.gif --extract frames
# 仅用于明确要求每帧 80 毫秒的等节拍，不用于一般调速或只改尺寸
python scripts/pack_gif.py frames resized.gif --delay-ms 80 --size 240x240
```

下面是从静帧编码的完整说明。保留动作原帧，后续改速度、停顿或尺寸都可以重新编码。

## 最短操作

在本技能目录下运行以下命令。用 `python3` 或 Windows 上指向同一环境的 `py` 替换 `python`。本项目验证过 Python 3.9.6 和 Pillow 11.3.0，复现实例时可固定这一 Pillow 版本。

```sh
python -m pip install "Pillow==11.3.0"
python scripts/pack_gif.py frames output/reaction.gif --fps 12
```

只将最终帧放进 `frames/`，支持 PNG、JPEG、静态 WebP。使用同一画布，保留动作所需的透明留白。脚本只读目录顶层，忽略隐藏文件，按文件名自然排序，例如 `pose2.png` 会早于 `pose10.png`。连续补零编号也适用于多镜头。安装好 Pillow 后，编码无需网络。

以下是四张方形帧的示例。起势两帧各 80 毫秒，爆点停留 240 毫秒，回收 120 毫秒。将末帧停顿写进时长，可避免重复制作相同的图片。

```sh
python scripts/pack_gif.py frames output/nod.gif --delay-ms 80,80,240,120 --size 320x320
```

多镜头可以直接依次接入各镜的帧目录。三个目录都可以从 `frame-001.png` 开始。每个目录内先自然排序，再按命令中给出的镜头顺序连接；请在接入前完成各镜独立的拆帧或补帧。若用逐帧时长，数值依三个镜头的最终播放顺序填写。

```sh
python scripts/pack_gif.py shot-01 output/portrait.gif --append shot-02 --append shot-03 --fps 12
```

| 参数 | 行为 |
| --- | --- |
| `--append shot-02` | 在第一镜之后接入另一帧目录，可重复。每个目录需含至少一张可用静帧，各镜画布尺寸一致。 |
| `--fps 12` | 默认 10 FPS。按累计时间分配 10 毫秒刻度，12 张、12 FPS 共 1.00 秒。 |
| `--delay-ms 80` 或 `--delay-ms 80,80,240,120` | 同一时长或逐帧时长，单位毫秒，须为 10 的倍数。与 `--fps` 二选一。 |
| `--size 360x640` | 默认用源帧尺寸。可按相同比例缩放，允许取整造成的一像素误差。若需要另一画幅，先在分镜阶段决定裁切或补边。 |
| `--matte "#FFFFFF"` | 将半透明像素合成到指定底色，适合对发丝、阴影和柔光边缘有要求的画面。默认使用二值透明。 |
| `--dither` | 启用 Floyd–Steinberg 抖动。照片渐变可以对比开启后的效果，扁平贴纸通常从默认关闭开始。 |
| `--max-bytes 900000` | 用你实际需要的字节预算替换数字。超过即报错，已存在的成品仍可使用。这个示例数值由创作者自定。 |
| `--force` | 允许替换同名目标文件。写入前先在同目录生成临时文件并解码核对。 |

## 透明、颜色与时间

- GIF 的帧延迟字段以百分之一秒为单位。使用 `loop=0` 编码无限循环；故意硬切可以保留，不要求自然衔接。用户报告特定客户端播放问题时再排查。[GIF89a 规范，第 23 节](https://www.w3.org/Graphics/GIF/spec-gif89a.txt) · [Pillow GIF 读写选项](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#gif)
- 单个 GIF 调色表最多有 256 种颜色。工具抽样所有帧建立共用颜色，透明镜头保留一个透明索引；默认透明度低于 128 的像素透明，其余为实色。这些编码取舍由工具处理，不新增边缘修图环节。[GIF89a 的图形控制扩展](https://www.w3.org/Graphics/GIF/spec-gif89a.txt) · [Pillow 颜色量化](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.quantize)
- 透明贴纸采用每帧播放后恢复背景的处理，使移开的手和飘走的物件露出透明底。量化后视觉相同的相邻帧会合并，停留总时长保留。成品至少要有两个可区分的画面。[Pillow 帧处置与时长选项](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#saving)
- 用户明确要求压缩时，可缩小画幅、减少冗余帧或关闭抖动，并保留原文件。平台另有限制时，按实际发布入口设置字节预算和尺寸；不为未提出的体积目标追加压缩循环。

## 编码器自带的文件检查

1. 命令成功后会报告输入数、编码帧数、尺寸、秒数、字节数和解码结果。脚本重新逐帧读取交付文件，核对无限循环标记、每帧时长、可见像素和透明轮廓；技术检查的对照物是量化后的目标帧。
2. 命令成功后直接交付，不再要求观看三个循环、联系表或参考图对比。技术检查不能判断笑点或人物身份，也不触发图像重生成。
